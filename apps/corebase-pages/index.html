The problem

Agents are useful. Unbounded agents are a liability.

Giving a browser a real shell is a security mistake. Giving it an opaque “do the thing” button is a trust mistake. CoreBase takes a third path: a deliberately small virtual workspace where each action is scoped, approved and recorded.

⌘

No browser shell

There is no eval, spawn or network call. The virtual shell implements a fixed command set over IndexedDB files.

◇

No implicit consent

Authority is granted per scope, target and expiry. Revocation is immediate and itself audited.

⤳

No invisible changes

Every lifecycle stage is appended to a canonical hash chain. If a link breaks, the UI says so.

What you get

A workspace that can explain itself.

Files, commands, approvals and history in one local environment.

▤

Persistent projects

Create projects and files in local IndexedDB. Edit with CodeMirror, track dirty state, save with intent.

Canonical JSON entries link to the previous hash. Integrity is checked on load and never silently repaired.

Offline agent adapter

A deterministic offline planner produces structured plans. The remote stub is explicitly disabled — no keys, no calls.

How it works

Intent to result, without the hand-waving.

Each stage is recorded before the next begins. Verification checks both exit status and expected state.

The human goal is captured verbatim.

Plan

Authorize

Required scopes are checked against grants.

Approve

A human sees the exact action and target.

Execute

The virtual adapter runs a bounded command.

Verify

Exit code and expected state must both match.

Persist

File changes are written locally and atomically.

Provenance

Fingerprints and hashes close the chain.

Strategic fit

CoreSkills writes the brief. CoreBase carries it out.

A capability authored in CoreSkills arrives with a manifest, a content identity and explicit scopes. CoreBase treats that as an intent: it plans, asks for authority, executes inside the sandbox, verifies, and records provenance.

  • Shared contracts keep the handoff machine-readable.
  • The same permission vocabulary powers requests and approvals.
  • Checksums travel with the capability so provenance survives the trip.

Quick start

Open the app. A sample project is seeded on first run with files and a terminal session. Switch to the Terminal tab and type help to see the bounded command set. Actions that touch files ask for approval before they run.

The adapter is a virtual shell over IndexedDB. It cannot reach your host filesystem, spawn processes or make network requests.

Virtual commands

Twelve commands, deliberately boring. Each has an explicit scope and a verifiable expected state.

Permissions

Decisions are default-deny. A grant is scoped, targeted and expiring; revocation writes an audit event so the history shows when authority ended.

approval request
{
  "adapter": "virtual-shell",
  "capability": "file.write",
  "target": "notes/ideas.md",
  "scopes": ["workspace.files.write"],
  "reason": "Append summary from the planned edit",
  "expiresAt": "2026-11-25T09:30:00Z"
}

Audit chain

Every entry is canonical JSON hashed with SHA-256 and linked to the previous hash. The chain starts at a genesis hash of sixty-four zeroes. Verification reports breaks; it never “fixes” them.

Honest by design. A valid chain proves continuity and integrity. It does not prove that an approved action was wise.

Storage & restore

Projects, files, terminal sessions, grants, checkpoints and settings live in a local IndexedDB database. Checkpoints capture file bytes plus the audit head, so restoring also rewinds provenance to the recorded state.

Questions

Straight answers.

Can it run commands on my computer?

No. The shell is an in-browser adapter over IndexedDB with twelve bounded commands. There is no host shell, process spawn, network access or file-system bridge.

What if an agent asks for something dangerous?

The plan is checked against scopes. Anything requiring authority opens an approval dialog showing the exact adapter, capability, target and reason. Deny it and nothing executes.

What does a broken audit chain look like?

The Audit tab reports a chain break with the affected entry. CoreBase never rewrites history to hide it.

Is the remote agent adapter active?

No. It is an explicit stub with no credentials and no API calls. The working planner is deterministic and offline.
